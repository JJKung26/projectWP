# ระบบร้านหมูกระทะผ่าน QR

ใช้ Node.js 24 (ทดสอบกับ 24.18.0), Express, EJS, SQLite และ Socket.IO

## เริ่มใช้งาน

1. บน Windows 64-bit ติดตั้ง Node.js 24 LTS แล้วเปิด `START.cmd` ระบบติดตั้ง dependencies และสร้าง .env พร้อม Secret ให้เมื่อย้ายเครื่อง
2. ระบบใช้ Cloudflare รอข้อความ `Cloudflare URL: https://...trycloudflare.com` ก่อนเปิดโต๊ะหรือแสดง QR
3. เปิด `http://localhost:3000/login` สำหรับพนักงาน ส่วนลูกค้าสแกน QR เพื่อเข้าลิงก์ HTTPS จากต่างเครือข่ายได้
4. ถ้ารันจาก Terminal เอง: `npm ci`, `node scripts/prepare-env.js`, `npm start`

เครื่อง Server ต้องเปิดเว็บและเชื่อมอินเทอร์เน็ตอยู่
เมื่อเริ่ม Server ใหม่ ลิงก์ Tunnel อาจเปลี่ยน ให้แสดงหรือพิมพ์ QR ใหม่ของโต๊ะเดิม
หากต้องการใช้เฉพาะใน Wi-Fi เดียวกัน ให้ตั้ง `PUBLIC_URL` เป็น IP ของเครื่อง Server เช่น `http://192.168.1.35:3000` แล้วรัน `npm run start:local`

## Cloudflare Tunnel

ปิด Server ที่ใช้พอร์ต 3000 ก่อน แล้วเปิด `START.cmd` หรือ `START-CLOUDFLARE.cmd` ทั้งสองไฟล์ใช้ Cloudflare หรือรัน `npm run start:cloudflare` บน Windows 64-bit ครั้งแรกจะดาวน์โหลด cloudflared จาก Cloudflare ลง tools/cloudflared.exe อัตโนมัติ ไม่ต้องมีบัญชีหรือโดเมน

รอข้อความ `Cloudflare URL: https://...trycloudflare.com` แล้วใช้ลิงก์นี้เปิดเว็บจากมือถือคนละเครือข่าย QR สั่งอาหารใช้ URL นี้อัตโนมัติ หน้าแคชเชียร์ในเครื่องยังอยู่ที่ http://localhost:3000/cashier/tables

ตัวเปิด Cloudflare ส่ง PUBLIC_URL ของรอบนั้นให้เว็บและ QR อัตโนมัติ ไม่ต้องตั้ง URL ใหม่ใน .env และไม่แก้ config.json หรือฐานข้อมูลธุรกรรม กด Ctrl+C เพื่อหยุดเว็บและ tunnel พร้อมกัน ถ้า tunnel หยุด เว็บจะหยุดด้วยเพื่อไม่ออก QR ที่ใช้ไม่ได้

Quick Tunnel เป็นลิงก์ชั่วคราวที่เปลี่ยนทุกครั้งที่เปิดใหม่ เมื่อเริ่มใหม่ให้แสดง/พิมพ์ QR ใหม่ของโต๊ะเดิม ประวัติและรอบบริการยังอยู่ ไม่ต้องเปิดโต๊ะซ้ำ หาก cloudflared ต่อไม่ได้ให้ดูข้อความผิดพลาดและลองใหม่

อ้างอิง: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [ดาวน์โหลด cloudflared](https://developers.cloudflare.com/tunnel/downloads/)

ทดสอบลูกค้าพร้อมกัน 60 คนผ่าน Cloudflare: `npm run test:cloudflare-load` รวมการโหลดรูปหน้าแรก หรือ `npm run test:cloudflare-load -- --orders-only` สำหรับการสั่งอาหารและ realtime ชุดทดสอบใช้พอร์ต 3215 และฐานข้อมูลชั่วคราวแยกจากร้าน ต้องติดตั้ง dependencies และมี tools/cloudflared.exe ก่อนรัน สามารถเปิดเว็บร้านที่พอร์ต 3000 ไว้ได้

ผลล่าสุดอยู่ใน [CLOUDFLARE-LOAD-TEST.md](CLOUDFLARE-LOAD-TEST.md) ชุดทดสอบแยกการเชื่อมต่อของลูกค้าแต่ละคน และผ่านการโหลดรูป การสั่งอาหาร และ realtime ผล JSON จะถูกเขียนทับเมื่อรันโหมดเดียวกันอีกครั้ง

## กติกาที่ใช้

- ลูกค้าเป็นจำนวนเต็มตั้งแต่ 1 ถึงความจุโต๊ะในฐานข้อมูล ราคาบุฟเฟต์มากกว่า 0 ถึง 10,000 บาท
- อาหาร 1–20 ชิ้นต่อเมนู สูงสุด 100 เมนูต่อคำขอ ตรวจทั้งคำขอก่อนบันทึก
- ต้องเสิร์ฟหรือยกเลิกรายการค้างทั้งหมดก่อนรับเงิน
- VAT 7% คิดจากยอดก่อนภาษี ปัด VAT เป็นสตางค์ แล้วปัดยอดรวมลงเป็นบาทครั้งเดียวทุกช่องทาง
- พร้อมเพย์สร้าง QR รับเงินจริงตามยอดสุทธิจาก config.json พนักงานตรวจเงินเข้าบัญชีก่อนยืนยัน ส่วนบัตรยังเป็นการจำลอง
- เงินสดรับทศนิยมได้ 2 ตำแหน่ง คำนวณเงินทอนจากยอดหลังปัด รับสูงสุด 1,000,000 บาท
- ชำระเงินสำเร็จแล้วโต๊ะกลับเป็น AVAILABLE ทันที พร้อมเปิดรับลูกค้ารอบใหม่
- รีเซ็ตรอบที่ยัง ACTIVE ได้เมื่อไม่มีอาหารที่ไม่ถูกยกเลิก หากมีอาหารต้องเช็กบิล
- ใบเปิดโต๊ะ QR แยกจากใบเสร็จ เลือก 80 มม. / 58 มม. แล้วกดพิมพ์เอง
- ใบเสร็จย้อนหลังเข้าจากผังโต๊ะ (แสดง 200 ใบล่าสุด) ข้อมูลอ่านจาก Bill/Payment ที่เก็บไว้
- ใบเสร็จหลังชำระแสดงแพ็กเกจบุฟเฟต์และยอดเงินรวม โดยไม่แสดงรายการอาหาร ส่วนหน้าเช็กบิลก่อนชำระยังมีรายการสำหรับตรวจสอบ
- เวลาแสดงและวันคิวใช้ Asia/Bangkok ฐานข้อมูลเก็บ timestamp เป็น UTC
- จัดการคิว → เลือกวัน → ติ๊กดูทุกสถานะ → พิมพ์ซ้ำ ใช้หมายเลขและเวลาเดิม ไม่สร้างคิวใหม่
- กดเรียกคิวเพื่อเริ่มเสียงผู้หญิงภาษาไทย เล่นจากไฟล์ในโปรเจกต์ จึงใช้เสียงเดียวกันทุกเครื่อง และมีข้อความเลขคิวบนหน้าจอ
- ปิดหน้าต่างด้วยปุ่มปิด, Escape หรือแตะพื้นหลังได้ ระบบคืน focus ไปยังปุ่มเดิม

ระบบปัจจุบันยังไม่มีคำสั่งเรียกพนักงานจากลูกค้า ไม่มีการตัดรอบอัตโนมัติหรือคิดค่าปรับตามเวลา/อาหารเหลือ ตัวเลขเวลาในผังโต๊ะเป็นเวลาใช้บริการสำหรับพนักงานดู

## ทดสอบและสำรองข้อมูล

`npm test` ทดสอบกับฐานข้อมูลชั่วคราวแยกจาก data/restaurant.db
ผ่าน 44 กรณี ครอบคลุม 30 คำขอพร้อมกัน, 10 โต๊ะ, Rollback, ชำระซ้ำ, ปัดเศษ, Socket และฐานข้อมูลเก่า
รวมการลองส่งคำขอเดิมหลังไม่ได้รับคำตอบ, โหลดหน้าใหม่ขณะของหมด, ป้องกันรีเซ็ตข้อมูลเก่า และฟอร์มไม่ถูกอัปเดตสดทับ

`npm run backup` สำรองฐานข้อมูลเป็นไฟล์ใหม่ใน backups/ ใช้ VACUUM INTO จึงรวมข้อมูลที่อยู่ใน WAL ด้วย

กู้ข้อมูล: ปิด Server ก่อน ย้ายโฟลเดอร์ data เดิมไปเก็บสำรอง แล้วสร้าง data ใหม่และคัดลอกไฟล์สำรองเป็น data/restaurant.db อย่านำ WAL ของฐานข้อมูลเดิมมาใช้กับไฟล์ที่กู้ใหม่

หาก startup ล้มเหลว ให้ดูข้อความ Startup failed:
- SESSION_SECRET ไม่ถูกต้อง: ตั้งค่าใหม่ใน .env
- SQLITE_CONSTRAINT: ข้อมูลเก่ามี ACTIVE/เลขคิว/Payment ซ้ำ ต้องสำรองแล้วตรวจข้อมูลก่อนแก้ ระบบไม่ลบให้อัตโนมัติ
- บัญชีเก่าไม่มี password_hash: รัน npm run seed:accounts
- พอร์ตถูกใช้: เปลี่ยน PORT และแก้ PUBLIC_URL ให้ตรงกัน
- PUBLIC_URL ไม่ถูกต้อง: หน้าแคชเชียร์ยังเปิดได้และแสดงคำแนะนำ แต่ต้องแก้ .env และเริ่ม Server ใหม่ก่อนเปิดโต๊ะ
- เน็ตหลุดขณะส่งอาหาร: รอปุ่มปลดล็อกแล้วกดลองส่งรายการเดิมอีกครั้ง ระบบใช้ key เดิมเพื่อป้องกันออเดอร์ซ้ำ
- คำสั่งค้างเกิน 12 วินาที: ระบบหยุดรอและปลดล็อกปุ่ม ครัว/เสิร์ฟควรดูสถานะล่าสุดก่อนลองใหม่

รายละเอียดการแก้และรายการซ้อมจริงอยู่ใน [FIXES.md](FIXES.md)

## พร้อมเพย์ตามยอดเช็กบิล

กำหนดหมายเลขที่ผูกกับบัญชีธนาคารแล้วใน `config.json` ช่อง `promptpayNumber` เป็นข้อความ เพื่อเก็บเลขศูนย์นำหน้า รองรับเบอร์มือถือ 10 หลักหรือเลขผู้เสียภาษี 13 หลัก ไม่ใช้ .env สำหรับพร้อมเพย์

หน้าเช็กบิล → รับชำระ → พร้อมเพย์ → ลูกค้าสแกน QR → พนักงานตรวจเงินเข้าครบยอด → ติ๊กยืนยันการตรวจ → ยืนยันรับเงิน ระบบออกใบเสร็จและเปลี่ยนโต๊ะเป็นว่าง ยอด QR มาจากฐานข้อมูล รวม VAT 7% และปัดเศษลงเป็นเต็มบาท เช่น 600.81 → 600.00 บาท

ใช้ promptpay-qr สร้าง payload และ qrcode สร้างรูปในเครื่อง ไม่ใช้ Payment Gateway และไม่มีการตรวจบัญชีธนาคารอัตโนมัติ การสแกนหรือแสดง QR ยังไม่บันทึกชำระ พนักงานต้องตรวจรายการรับเงินจริงในบัญชีร้าน

สเปกและไลบรารีอ้างอิง: [Thai QR Payment ธปท.](https://www.bot.or.th/content/dam/bot/documents/th/our-roles/payment-systems/about-payment-systems/ThaiQRCode_Payment_Standard.pdf), [promptpay-qr](https://github.com/dtinth/promptpay-qr)

## ย้ายโปรเจกต์ไปเครื่องอื่น

ZIP มี config.json, package.json, package-lock.json และโฟลเดอร์โค้ด/รูป/เสียง ไม่คัดลอก node_modules จากเครื่องเดิม เพราะ SQLite มีส่วนที่ขึ้นกับระบบปฏิบัติการ

1. ติดตั้ง Node.js 24 LTS และแตก ZIP
2. Windows: เปิด START.cmd ระบบติดตั้ง dependencies และสร้าง .env สำหรับเครื่องใหม่อัตโนมัติ โดยไม่แก้หมายเลขพร้อมเพย์
3. ตัวเปิด Cloudflare ในชุดนี้รองรับ Windows 64-bit หากใช้ระบบอื่นให้ติดตั้ง cloudflared ของระบบนั้นและเปิด tunnel เอง จากนั้นตั้ง PUBLIC_URL และรัน npm run start:local
4. เปิด http://localhost:3000/login ใช้บัญชีสาธิตเดิม และใช้ลิงก์ HTTPS จาก terminal เมื่อต้องให้มือถือที่ใช้คนละเครือข่ายเข้าเว็บ

ZIP เป็นชุดโค้ดพร้อมข้อมูลตั้งต้น ระบบสร้างฐานข้อมูลใหม่ตอนรัน ไม่รวมฐานข้อมูลธุรกรรมหรือ .env ของเครื่องเดิม หากต้องการย้ายประวัติด้วย ให้ใช้ไฟล์สำรองฐานข้อมูลตามขั้นตอนกู้ข้อมูลด้านบน


## ราคาเด็ก

หน้าเปิดโต๊ะและจัดโต๊ะให้คิวแยกจำนวนผู้ใหญ่ เด็กสูง 90–120 ซม. และเด็กต่ำกว่า 90 ซม. ทานฟรี กรอกราคาผู้ใหญ่และราคาเด็กได้ โดยเริ่มต้นที่ 279 และ 179 บาทตามลำดับ เด็กสูงเกิน 120 ซม. ใช้ราคาผู้ใหญ่ จำนวนลูกค้ารวมทุกกลุ่มต้องไม่เกินที่นั่งของโต๊ะ และตรงกับบัตรคิว

ยอดบุฟเฟต์ = (จำนวนลูกค้ารวม − เด็กที่เสียเงิน − เด็กทานฟรี) × ราคาผู้ใหญ่ + เด็กที่เสียเงิน × ราคาเด็ก จากนั้นคิด VAT และปัดเศษตามเดิม ราคาเด็กเก็บไว้ในรอบบริการและใบเสร็จเพื่อให้พิมพ์ซ้ำได้ตรงกับตอนชำระ บิลเก่าที่ไม่ได้แยกเด็กยังใช้ยอดเดิม
